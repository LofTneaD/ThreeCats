## Выбор режима рендеринга Blazor

Для проекта выбран режим **Interactive Server** в приложении Blazor Web App.

В этом режиме интерактивная логика компонентов выполняется на сервере, а взаимодействие с браузером организуется через SignalR. Это позволяет не загружать в браузер сборки .NET и основную серверную логику приложения.

Режим подходит для разрабатываемой системы ветеринарной клиники, поскольку бизнес-логика, работа с базой данных и обработка запросов будут выполняться на сервере.

**Почему не WebAssembly?**

Blazor WebAssembly выполняет .NET-код непосредственно в браузере. Такой вариант увеличивает объём кода, загружаемого клиентом, и требует особого внимания к разграничению клиентской и серверной логики. Для проекта, ориентированного на серверную работу с PostgreSQL и авторизацией, этот режим не является приоритетным.

**Почему не Auto?**

Режим Auto может использовать серверную интерактивность и WebAssembly в зависимости от доступности клиентской среды и загрузки необходимых ресурсов. Он усложняет первоначальную настройку и тестирование, а его преимущества не являются необходимыми для текущих требований проекта.
